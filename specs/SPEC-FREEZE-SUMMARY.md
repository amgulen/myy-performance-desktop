## 一、本版本覆盖范围

### 软件形态
- Windows桌面应用程序（Electron + React + TypeScript）
- SQLite本地数据库
- 解压即用绿色软件，GitHub Release分发

### 绩效模型（7类，含2类变体）
| 模型 | 说明 |
|---|---|
| 比例模型（固定比例） | 分类金额×固定比例，如挂号费80%、一人一方20% |
| 比例模型（动态比例/积分制） | 积分×(绩效总额÷总积分)，积分单价动态计算 |
| 固定金额模型 | 按人次/次数/份数发放固定金额，如夜班费、住院病历费 |
| 计件模型 | 数量×单价×岗位系数，如检验科各类项目计件 |
| 阈值后计提模型 | 达到基准线后仅对超出部分计提，如非药物特色治疗超额部分 |
| 评分考核模型 | 多指标加权评分×等级系数，如出诊专家综合考核 |
| 扣罚/质量控制模型 | 投诉、报告错误等扣减绩效，如报告错误、质控不合格 |

### 数据来源
- **ABC数字医疗云开放平台**（V1正式交付版必须完成接口接入与数据同步）
- **Excel导入**（开发测试期验证手段，正式交付后作为异常兜底和历史补录方式长期保留）
- **手工录入**（补充、修正与特殊情况处理方式，长期保留）
- 不假设HIS/LIS/收费系统存在

### 功能模块（第一阶段MVP）
| 模块 | 功能 |
|---|---|
| 项目初始化 | 首次启动配置、数据路径选择、数据库初始化 |
| 数据库 | SQLite本地存储 |
| 员工管理 | 科室管理、员工管理、岗位分类、人员信息 |
| ABC接口接入与数据同步 | ABC接口配置、鉴权、连接测试、字段映射、数据同步、同步日志、失败重试 |
| 规则配置 | 创建/编辑/版本管理绩效规则（固定比例/动态比例/固定金额/计件/阈值/评分/扣罚） |
| Excel兜底导入 | 支持导入Excel数据用于开发测试、异常兜底和历史补录 |
| 绩效计算 | 一键计算，支持全部7种绩效场景，支持多规则叠加 |
| 结果展示 | 汇总视图、明细视图、计算路径追溯视图 |
| 结果控制 | 允许人工调整，保留原始结果，记录调整日志；支持结果锁定 |
| Excel导出 | 汇总表导出、明细表导出 |
| 备份恢复 | 手动备份、自动备份、导入恢复 |

### 配置能力
- 所有绩效规则（比例/金额/权重/阈值/等级/扣罚）均可配置
- 规则版本管理，支持随时修改
- AppId/AppSecret本地配置，AppSecret本地加密存储

## 二、不包含范围

以下内容在本版本中不实现，留待后续阶段：

| 内容 | 原因 |
|---|---|
| HIS/LIS/收费系统接口 | 医院当前无这些系统，不作为设计前提 |
| 实时数据同步 | 数据来源未确认 |
| 多用户/网络版 | 本版本确认单机单用户 |
| 并发控制 | 同上 |
| BI分析/数据可视化大屏 | 第一阶段MVP不含此内容 |
| 手机端 | 同上 |
| 审计日志 | 制度要求落地后补充 |
| Web版/Linux版 | 需求定位为Windows桌面软件 |

## 三、已确认核心决策

| # | 决策 | 说明 |
|---|---|---|
| 1 | 绩效结果允许人工调整 | 保留原始计算结果+调整记录 |
| 2 | 不强制人工确认环节 | 不增加审批流，但必须遵循统一标准计算流水线 |
| 3 | 支持结果锁定 | 防止误改 |
| 4 | V1正式交付必须完成ABC接口接入 | ABC接口接入与数据同步是正式交付版完整可用的必要条件 |
| 5 | Excel导入为开发测试与兜底方式 | 系统根据配置自动生成模板，正式交付后仍长期保留 |
| 6 | 手工录人为辅助功能 | 使用频率低但必须支持，不限制数据量 |
| 7 | 积分制归入比例模型变体 | 不作为独立模型类型，设计阶段避免重复 |
| 8 | 制度调整频率不做限制 | 系统支持随时修改规则 |
| 9 | 规则版本管理必须支持 | 避免历史结果被污染 |
| 10 | AppSecret本地加密 | 不上传云端 |
| 11 | 单机单用户 | 不支持多用户并发 |
| 12 | V1不做角色权限和账号体系 | 所有系统操作默认由单一管理员完成；财务、医生、科室负责人等仅为报表使用方或业务参与方 |
| 13 | 统一绩效原子数据为计算输入 | ABC、Excel、手工录入数据必须先归一化，不得直接进入计算 |
| 14 | 标准计算流水线为设计约束 | 数据导入/同步、归一化、去重冲突、冲减、规则匹配、基础计算、阈值、评分、扣罚、人工调整、锁定、导出备份 |
| 15 | core必须独立于Electron | 规则引擎、计算引擎、数据标准模型、Excel导入导出、ABC字段映射应尽量平台无关，便于未来云端迁移 |

## 四、下一阶段目标（设计阶段）
