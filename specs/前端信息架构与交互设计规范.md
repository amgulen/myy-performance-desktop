# 前端信息架构与交互设计规范

**版本：** V1.0
**日期：** 2026-05-25
**状态：** 界面设计基线
**技术边界：** Electron + React + TypeScript；UI 不承载计算规则

---

## 1. 产品体验目标

本系统面向本地单机管理员，用于配置规则、同步或导入数据、发起计算、核查追溯、导出结果和执行备份。界面设计目标不是展示繁复大屏，而是让高风险操作清楚、可核查、不会误改。

设计关键词：

- 稳定：日常操作路径固定，避免隐藏关键状态。
- 清楚：数据来源、规则版本、计算状态、锁定状态可见。
- 克制：以表格、表单和步骤流为主，不引入无业务价值的可视化装饰。
- 可追溯：从汇总结果能够逐层钻取到计算明细和原始来源。
- 防误操作：导入、复算、锁定、恢复等关键动作有明确影响说明。

## 2. 导航结构

应用使用左侧一级导航与页面顶部上下文栏。V1 不展示用户头像、权限菜单或协作功能。

| 一级模块 | 核心页面 | 主要任务 |
|---|---|---|
| 首页 | 工作概览 | 查看待处理映射、最近同步、待锁定周期、备份状态 |
| 基础资料 | 科室、人员、岗位、项目分类与映射 | 维护计算基础信息 |
| 数据中心 | ABC同步、Excel导入、手工录入、异常处理 | 收集并归一化数据 |
| 规则配置 | 规则模板、规则版本、试算 | 配置可变制度规则 |
| 绩效计算 | 计算批次、发起计算、差异复算 | 按周期生成结果 |
| 结果追溯 | 汇总、明细、单笔路径、调整与锁定 | 核查并确定结果 |
| 报表导出 | 报表任务、导出记录 | 输出财务使用数据 |
| 系统维护 | ABC配置、备份恢复、本地设置 | 管理本地运行能力 |

## 3. 应用框架

### 3.1 页面骨架

| 区域 | 内容 |
|---|---|
| 左侧导航 | 固定模块入口与当前选中状态 |
| 顶部上下文栏 | 当前计算周期、数据状态、必要的页面操作 |
| 主工作区 | 表格、配置表单、计算步骤或追溯信息 |
| 右侧详情抽屉 | 不离开列表查看记录详情、错误和追溯步骤 |
| 全局通知区 | 同步/导入任务进度、失败提醒、备份完成提示 |

### 3.2 全局状态提示

任何涉及结果可信度的状态都应使用文字与颜色共同表示，不只依靠颜色：

| 状态 | 表示方式 |
|---|---|
| 草稿规则 | 中性标签“草稿” |
| 已启用规则版本 | 成功标签“生效中”，展示生效日期 |
| 数据待映射 | 警告标签“待处理”，可点击定位问题 |
| 计算未锁定 | 信息标签“可复算” |
| 结果已锁定 | 明确标签“已锁定”，主操作区禁用直接覆盖 |
| 同步失败 | 错误标签“失败”，提供失败批次详情 |

## 4. 关键业务流程界面

### 4.1 首次启动向导

步骤顺序：

1. 选择本地数据目录。
2. 配置备份位置与自动备份策略。
3. 配置 ABC 连接，允许暂时跳过并使用 Excel 验证模式。
4. 导入或复制参考规则模板，默认保持草稿。
5. 进入首页并显示仍需处理的事项。

向导不得引导用户把示例规则直接当成正式规则启用。

### 4.2 ABC 同步页面

必须展示：

- 当前接口环境、连接状态、最近成功同步时间。
- 数据类型选择、同步时间窗口、回看区间。
- 当前批次的成功数、失败数、待处理数。
- 重试入口、错误详情、字段映射版本。
- 对账入口与差异结果。

AppSecret 输入框只支持设置或替换，不支持读取明文。

### 4.3 Excel 导入页面

用户流程：

1. 下载对应模板和字段说明。
2. 选择文件并解析预览。
3. 查看成功、错误、重复、待映射行分组。
4. 确认合法行导入，错误行导出反馈。
5. 查看导入批次及生成的原子数据数量。

页面必须明确提示：“导入的是业务数据，不是最终绩效金额”。

### 4.4 规则配置页面

规则编辑采用“规则基本信息 + 适用范围 + 参数 + 生效版本 + 试算”结构：

| 区域 | 内容 |
|---|---|
| 基本信息 | 名称、类型、用途说明、状态 |
| 适用范围 | 人员、岗位、科室、项目分类、数据来源、期间 |
| 参数配置 | 根据规则类型显示结构化参数字段 |
| 版本与生效 | 版本号、生效/失效时间、变更原因 |
| 试算 | 输入样例数据，展示计算路径，不写入正式结果 |

规则参数必须用结构化表单表达，不允许用户直接填写不可验证的任意脚本。

### 4.5 计算与结果追溯页面

计算页按流水线阶段展示状态：

```text
数据准备 -> 归一化 -> 去重/冲减 -> 规则匹配 -> 基础计算
        -> 阈值 -> 评分 -> 扣罚 -> 调整 -> 锁定/导出
```

结果页面提供三层查看：

| 层级 | 内容 |
|---|---|
| 汇总 | 按人员、科室、周期查看最终金额和状态 |
| 明细 | 查看规则类型、来源类别、基础金额、扣罚和调整 |
| 追溯 | 查看原始单号、原子数据、冲减链、规则版本和每步计算式 |

### 4.6 锁定、复算与恢复

| 操作 | 交互保护 |
|---|---|
| 锁定结果 | 展示周期、条数、金额汇总与锁定后的影响，再确认 |
| 对锁定期新增数据 | 页面显示影响提示，不自动覆盖结果 |
| 发起复算 | 创建新批次，要求填写原因并展示差异 |
| 从备份恢复 | 显示将覆盖的本地数据范围，要求二次确认并自动生成恢复前备份 |

## 5. 前端与业务层边界

| 前端可以做 | 前端禁止做 |
|---|---|
| 展示规则参数表单和输入校验反馈 | 在组件中写比例、阈值、金额或等级判断 |
| 调用应用服务发起同步、导入、计算与导出 | 直接访问 SQLite 或拼装最终绩效 |
| 展示由 `core` 返回的计算路径 | 根据页面状态临时改变流水线顺序 |
| 展示字段映射和待处理问题 | 将 Excel/ABC 原始数据直接算成结果 |
| 实现交互保护和可访问性 | 以隐藏按钮替代业务锁定状态 |

## 6. 视觉与可用性标准

进入实际 UI 实现前应先形成可审阅的界面概念图和设计令牌；实现后使用浏览器或 Electron 渲染截图逐页核对。

### 6.1 视觉方向

- 采用清晰、安静的管理工具风格，强调数据可信与操作安全。
- 内容密度以桌面办公环境为准，结果和追溯页面优先使用可筛选表格，不将数据表改造成卡片墙。
- 使用单一明确的主色作为操作强调，警告、错误、锁定状态使用语义颜色。
- 所有金额、日期、状态和表格列保持对齐且便于扫描。

### 6.2 基础令牌范围

实现前应确定并统一维护：

- 字体、字号层级、行高和金额数字样式。
- 背景、表面、边框、主色、成功、警告、错误和锁定状态颜色。
- 间距、圆角、阴影、表格密度、表单高度。
- 按钮、输入框、表格、状态标签、步骤条、详情抽屉和确认弹窗组件变体。

### 6.3 无障碍与可操作性

- 状态不能只通过颜色表达。
- 表单错误应靠近字段并提供修复说明。
- 键盘可完成表格筛选、表单编辑和弹窗确认/取消。
- 关键操作按钮使用具体动作文本，例如“锁定 2026-05 结果”，避免模糊的“确认”。
- 表格导出和导入结果必须有文本摘要，不能只显示图形进度。

## 7. 前端验收门槛

| 范围 | 验收要求 |
|---|---|
| 信息架构 | 一级导航覆盖 V1 全部工作流程，无权限或云端扩展入口 |
| 规则配置 | 七类规则均有结构化配置和试算入口 |
| 数据来源 | ABC、Excel、手工、待处理和冲减状态可区分 |
| 追溯 | 从汇总结果可钻取到原始单号、规则版本和计算过程 |
| 高风险操作 | 锁定、复算、恢复、替换凭据有影响说明和确认交互 |
| 视觉质量 | 实施前有界面概念；实施后截图与概念逐屏核查 |
| 自动验证 | 核心交互流程通过 Playwright 或等价的真实界面验证 |
