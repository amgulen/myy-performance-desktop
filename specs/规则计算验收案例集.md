# 规则计算验收案例集

**版本：** V1.0
**日期：** 2026-05-25
**状态：** 开发验收基线
**说明：** 所有数字均为测试配置，不代表院方最终制度标准

---

## 1. 使用目的

本案例集用于验证规则模型、计算流水线和追溯结果是否正确。测试时将数字作为可编辑规则版本导入，不允许把案例中的数值写入执行器代码。

每个案例都必须验证：

- 输入原子数据和来源批次可见。
- 命中规则及具体规则版本可见。
- 中间计算步骤可见。
- 未命中、冲减、调整与锁定行为符合设计。

## 5. 案例 C：计件与岗位系数

| 项目 | 单价 |
|---|---:|
| 血常规 | 0.40 |

| 输入项目 | 数量 |
|---|---:|


## 6. 案例 D：阈值后计提与成本扣减

**测试规则：**

- 计提基数：扣除耗材成本后的净收入。
- 基准线：`50,000.00`。
- 超出部分计提比例：`45%`。

| 输入 | 值 |
|---|---:|
| 特色治疗收费收入 | 70,000.00 |
| 已确认耗材成本 | 5,000.00 |

**预期结果：**

```text
净收入 = 70,000.00 - 5,000.00 = 65,000.00
超出部分 = 65,000.00 - 50,000.00 = 15,000.00
绩效 = 15,000.00 x 45% = 6,750.00
```

变体验证：若该规则配置为不额外扣除耗材成本，则在已完成退费/作废冲减后的有效收费为 `70,000.00` 时，预期为 `(70,000.00 - 50,000.00) x 45% = 9,000.00`，证明成本扣减口径由配置控制；任何场景均不得绕过退款冲减。

## 7. 案例 E：动态积分制

**测试规则：** 当前计算周期绩效总额 `12,000.00`，全院有效总积分 `1,000`。

| 输入 | 值 |
|---|---:|
| 医师甲个人有效积分 | 80 |

**预期结果：**

```text
积分单价 = 12,000.00 / 1,000 = 12.00
医师甲绩效 = 80 x 12.00 = 960.00
```

变体验收：将结算周期配置为季度后，计算批次必须引用季度总额与季度总积分，不能沿用月度汇总值。

## 8. 案例 F：评分系数修正

**测试规则：**

| 维度 | 权重 | 医师甲得分 |
|---|---:|---:|
| 工作量 | 40% | 90 |
| 医疗质量 | 30% | 80 |
| 患者满意度 | 20% | 95 |
| 科研教学 | 10% | 70 |

等级配置：综合得分达到 `85` 且小于 `90` 时，绩效系数为 `1.10`。基础绩效为 `1,000.00`。

**预期结果：**

```text
综合得分 = 90 x 40% + 80 x 30% + 95 x 20% + 70 x 10%
         = 86
修正后绩效 = 1,000.00 x 1.10 = 1,100.00
```

## 9. 案例 G：扣罚处理

**测试规则：** 已完成评分处理后的绩效发生“报告单错误”，扣除当期对应计件绩效的 `10%`。

| 输入 | 值 |
|---|---:|
| 技师乙计件绩效 | 200.00 |
| 质量事件 | 报告单错误 1 次 |

**预期结果：**

```text
扣罚 = 200.00 x 10% = 20.00
扣罚后结果 = 200.00 - 20.00 = 180.00
```

顺序要求：扣罚必须在基础计件结果形成后执行。

## 10. 案例 H：部分退费冲减

**测试规则：** 治疗项目按净收费金额 `20%` 计提。

| 业务记录 | 金额 |
|---|---:|
| 原收费记录 | 1,000.00 |
| 关联部分退费 | -200.00 |

**预期结果：**

```text
有效净收费 = 1,000.00 - 200.00 = 800.00
绩效 = 800.00 x 20% = 160.00
```

追溯要求：正向记录和退费记录同时展示，不得只保存冲减后的 `800.00`。

## 11. 案例 I：多规则叠加与人工调整

医师甲在当月命中：

| 阶段 | 结果 |
|---|---:|
| 固定比例绩效 | 800.00 |
| 住院病历固定金额 | 300.00 |
| 评分系数修正前基础合计 | 1,100.00 |
| 评分系数 | 1.10 |
| 质量扣罚 | -50.00 |
| 人工调整（有原因） | +30.00 |

**预期结果：**

```text
基础合计 = 800.00 + 300.00 = 1,100.00
评分后 = 1,100.00 x 1.10 = 1,210.00
扣罚后 = 1,210.00 - 50.00 = 1,160.00
最终结果 = 1,160.00 + 30.00 = 1,190.00
```

追溯要求：原始计算结果 `1,160.00` 与人工调整后结果 `1,190.00` 均保留，并记录调整原因和时间。

## 12. 案例 J：锁定后补录或冲减

1. 先将医师甲 `2026-05` 结果锁定。
2. 导入一笔发生时间属于 `2026-05` 的迟到退费记录。

**预期行为：**

- 原锁定结果不被直接改写。
- 系统提示存在影响已锁定周期的新数据。
- 管理员可发起新的复算批次。
- 新旧批次差异、触发数据和规则版本均可追溯。

## 13. 案例 K：未配置规则或映射

| 输入异常 | 预期行为 |
|---|---|
| 项目未能映射到分类 | 数据进入待映射清单，不进入计算 |
| 需要岗位系数但未配置 | 结果标记待处理，不隐式使用 `1` |
| 评分指标缺失 | 按规则配置决定阻断或忽略，不由代码臆断 |
| 冲减找不到原单 | 进入待关联列表，不生成正式锁定结果 |

## 14. 验收清单

| 验收点 | 通过条件 |
|---|---|
| 配置化 | 修改测试规则参数后结果随版本变化，不修改代码 |
| 版本化 | 每笔结果能读取使用的规则版本 |
| 来源统一 | ABC 模拟记录与 Excel 数据可执行同一案例 |
| 冲减 | 正向与冲减均保留且净额正确 |
| 顺序 | 阈值、评分、扣罚、调整顺序固定 |
| 锁定 | 新数据不覆盖已锁定批次 |
| 可解释 | 界面和导出可显示完整路径 |
