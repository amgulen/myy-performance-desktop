# ABC接口映射与同步策略详细设计

**版本：** V1.0
**日期：** 2026-05-25
**状态：** 可实施设计稿（真实字段待联调绑定）
**依赖：** `ABC-API-CAPABILITY-REPORT.md`、`数据模型设计文档.md`

---

## 1. 目标与边界

ABC 是 V1 正式交付必须具备的主要业务数据来源。本设计定义 ABC 适配层与 `core` 之间的稳定契约，使应用可以先依据逻辑模型完成开发，再在取得真实凭据和响应样例后绑定外部字段。

ABC 适配层只负责获取、保存和归一化来源数据，不直接计算绩效。统计类接口仅用于对账，不作为唯一计算输入。

接口地址必须作为系统配置项。现有资料中的 `https://open-region2.abcyun.cn/` 为初期评估入口；2026-05-25 核验到的官方开放平台入口为 `https://open.abcyun.cn/`。运行时以医院实际分配的接口地址和文档版本为准。

---

## 2. 适配层职责

| 职责 | 输出 |
|---|---|
| 配置与凭据管理 | 接口地址、AppId、加密后的 AppSecret、连接状态 |
| 鉴权与连接测试 | 鉴权结果、失败原因、平台时间/环境信息（若接口提供） |
| 拉取来源业务数据 | 不可变的原始响应记录和同步批次 |
| 字段映射 | 外部字段到来源标准记录的映射版本 |
| 归一化调用 | 可进入 `core` 的绩效原子数据候选记录 |
| 重试与断点续传 | 可恢复的同步游标和失败明细 |
| 对账辅助 | 统计接口快照与本地计算汇总差异 |

## 3. 接口能力分组

接口路径和外部字段名必须在联调时从真实文档/响应样例确认。开发期先按以下能力标识实现适配端口：

| 能力标识 | 用途 | 是否计算输入 | 关键逻辑字段 |
|---|---|---|---|
| `organization.departments.list` | 同步科室 | 是，作为基础资料 | 外部科室ID、编码、名称、状态 |
| `organization.staff.list` | 同步人员 | 是，作为基础资料 | 外部人员ID、工号、姓名、科室、岗位、状态 |
| `billing.charges.list` | 收费业务记录 | 是 | 单号、行号、人员、项目、金额、数量、发生时间、状态 |
| `billing.refunds.list` | 收费退费 | 是 | 退款单号、原单号、退款金额/数量、时间、原因 |
| `prescription.items.list` | 处方和药品项目 | 是 | 处方号、医生、项目、数量、金额、类型 |
| `lab.orders.list` | 检查检验项目 | 是 | 检验单号、执行人员、项目、数量、状态、时间 |
| `lab.voids.list` | 检验作废 | 是 | 作废单号、原检验单号、时间、原因 |
| `dispensing.returns.list` | 退药 | 是 | 退药单号、原处方/发药单号、数量、金额 |
| `execution.records.list` | 实际执行记录 | 条件启用 | 执行单、执行人员、项目、数量、完成时间 |
| `statistics.performance.detail` | 平台统计结果 | 否，仅对账 | 期间、人员/科室、平台汇总金额 |

## 4. 配置模型

### 4.1 连接配置

| 配置项 | 说明 | 保护要求 |
|---|---|---|
| `baseUrl` | 医院所属 ABC 环境地址 | 支持修改并显示当前环境 |
| `appId` | 应用标识 | 可显示，禁止写入导出报表 |
| `appSecret` | 应用密钥 | 本地加密，只允许覆盖更新，不回显原文 |
| `authMode` | 鉴权模式 | 由联调绑定，可配置实现 |
| `timeoutMs` | 请求超时 | 可配置，记录使用值 |
| `pageSize` | 请求页大小 | 受平台限制约束 |
| `maxRetries` | 自动重试次数 | 不对鉴权失败无限重试 |
| `syncWindowDays` | 默认拉取时间窗口 | 支持日/月批次 |

### 4.2 字段映射版本

每类接口使用独立映射配置版本：

| 字段 | 说明 |
|---|---|
| 映射标识 | 对应能力标识 |
| 文档/环境版本 | 平台环境或响应样例版本描述 |
| 外部字段路径 | 真实响应 JSON 中字段路径，联调后配置 |
| 内部逻辑字段 | 本文定义的标准字段 |
| 转换器 | 时间、金额、枚举、正负号等转换方式 |
| 必填规则 | 缺失后记录是否可归一化 |
| 生效时间 | 新映射适用的同步批次时间 |
| 状态 | 草稿、启用、停用、归档 |

映射改变时，不覆盖已存的原始响应与既有原子数据追溯关系。

## 5. 内部来源标准记录

来源记录位于 ABC 适配层和绩效原子数据之间，保存原始响应及可读的逻辑字段。

### 5.1 通用字段

| 内部字段 | 必填 | 说明 |
|---|---:|---|
| `sourceRecordId` | 是 | 本地来源记录唯一标识 |
| `capabilityKey` | 是 | 接口能力标识 |
| `externalRecordId` | 是 | ABC 原始记录ID或由单号/行号构成的稳定标识 |
| `externalBusinessNo` | 是 | 原业务单号 |
| `externalLineNo` | 否 | 明细行标识 |
| `occurredAt` | 是 | 业务发生时间 |
| `fetchedAt` | 是 | 拉取时间 |
| `syncBatchId` | 是 | 同步批次 |
| `mappingVersionId` | 是 | 使用的字段映射版本 |
| `rawPayloadRef` | 是 | 原始响应保存引用 |
| `recordStatus` | 是 | 正常、取消、作废、退款、退药、未知 |

### 5.2 绩效相关字段

| 内部字段 | 说明 |
|---|---|
| `staffExternalId` | 绩效归属或执行人员外部标识 |
| `departmentExternalId` | 科室外部标识 |
| `projectExternalId` | 项目/药品/检验项目外部标识 |
| `projectName` | 来源项目名称 |
| `quantity` | 原始数量 |
| `amount` | 原始金额 |
| `originalBusinessNo` | 冲减记录关联的原业务单号 |
| `reversalQuantity` | 退款/退药/作废对应数量 |
| `reversalAmount` | 退款/退药对应金额 |

无法识别人员、项目、单号、金额或发生时间的数据不得直接生成可计算原子数据，进入映射待处理列表。

## 6. 到绩效原子数据的映射

| 来源标准字段 | 原子数据字段 | 映射规则 |
|---|---|---|
| `staffExternalId` | 人员 | 通过人员映射表解析；未映射则待处理 |
| `departmentExternalId` | 科室 | 通过科室映射表解析；允许随人员默认科室补齐并留痕 |
| `projectExternalId` / `projectName` | 项目、项目分类 | 通过项目分类映射配置解析 |
| `quantity` | 数量 | 标准化为十进制数量 |
| `amount` | 金额 | 标准化为人民币金额，保存来源精度 |
| `occurredAt` | 发生时间、计算周期 | 按配置的期间规则归属 |
| `capabilityKey` | 数据来源 | 固定为 `ABC` 并附接口能力标识 |
| `externalBusinessNo` | 原始单号/业务单号 | 原样保存 |
| `recordStatus` | 冲减/作废标识 | 退款、退药、作废生成冲减语义 |
| `rawPayloadRef` / `syncBatchId` | 可追溯来源 | 始终保留关联 |

## 7. 同步策略

### 7.1 首次同步

1. 管理员配置连接信息并执行连接测试。
2. 先同步科室、人员、项目基础信息。
3. 展示未映射项目和人员，允许配置分类或修正映射。
4. 按指定起止日期同步业务明细、退费/作废/退药记录。
5. 生成来源记录和原子数据候选。
6. 对映射失败和数据异常进行处理后，才可进入计算。

### 7.2 增量同步

| 策略 | 设计 |
|---|---|
| 时间窗口 | 以业务发生时间为主、同步游标为辅；默认窗口可配置 |
| 回看区间 | 每次同步重拉最近若干日，捕获延迟退费或作废；天数可配置 |
| 幂等键 | 能使用外部记录ID时优先使用，否则采用能力标识 + 单号 + 行号 + 状态 |
| 变更检测 | 同一幂等键的响应内容变化形成新来源快照，不覆盖旧记录 |
| 同步方式 | V1 使用主动拉取，不要求实时推送 |

### 7.3 冲减同步

退费、作废和退药必须独立同步并与原记录关联：

- 能关联原单时，产生对应冲减原子数据。
- 仅能取得冲减记录但暂时不能关联原单时，标记为待关联，不进入锁定计算。
- 部分退款和部分退药保留数量、金额两类冲减口径。
- 新同步到的跨期冲减不得改写已锁定结果，应触发新计算批次差异提示。

## 8. 错误、重试与日志

| 场景 | 处理策略 |
|---|---|
| 超时、临时网络错误、平台限流 | 指数退避重试，次数与等待上限配置化 |
| 鉴权失败 | 停止批次并提示更新配置，不自动持续重试 |
| 单页数据失败 | 批次记录失败游标，支持从失败页继续 |
| 单条字段缺失 | 保存原始响应，进入待处理清单，不丢弃整批 |
| 映射版本错误 | 暂停归一化，不删除来源原始记录 |
| 重复数据 | 幂等处理并记录重复或内容变化原因 |

同步日志至少记录批次、能力标识、时间范围、映射版本、请求数量、成功数、失败数、待处理数、重试次数和错误摘要。日志不得记录 AppSecret、鉴权 token 或完整敏感响应内容。

---

## 9. 对账策略

对账不替代计算，只检验数据链路的可信度：

| 对账对象 | 本地口径 | 平台口径 | 差异处理 |
|---|---|---|---|
| 收费净额 | 正向收费 - 退款/退药冲减 | ABC 统计收费明细 | 输出缺单、金额差异 |
| 检验项目数量 | 有效检验原子数据净数量 | ABC 检验/执行统计 | 输出作废或项目映射差异 |
| 人员业绩辅助值 | 本地规则计算汇总 | ABC 执行业绩明细 | 仅供核查，不覆盖本地结果 |

---

## 10. 联调与验收门槛

取得真实环境信息后，ABC 接入必须通过以下验收：

1. 成功配置凭据并通过连接测试，AppSecret 不可回显。
2. 以实际响应样例建立并启用字段映射版本。
3. 能同步人员、收费、处方、检验、退费/作废/退药等所需记录。
4. 重复同步同一窗口不产生重复可计算数据。
5. 退费和作废可关联正向记录并形成冲减追溯。
6. 异常字段不会绕过待处理流程进入计算。
7. 统计对账能够输出差异，而不是覆盖本地计算结果。
