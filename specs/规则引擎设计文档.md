# 规则引擎设计文档

**版本：** V1.0  
**日期：** 2026-04-26  
**状态：** 设计阶段草案  

---

## 1. 设计目标

规则引擎负责将绩效原子数据、人员/科室/岗位信息、项目分类、规则版本和计算周期组合起来，输出可追溯的计算结果。

规则引擎必须：

- 不写死比例、金额、权重、阈值、岗位系数、扣罚金额
- 支持规则版本、生效时间和停用状态
- 支持多规则叠加
- 支持规则优先级：人员 > 岗位 > 科室 > 全院
- 避免大量if/else堆叠
- 围绕标准计算流水线执行

---

## 2. 规则类型

V1规则类型包括：

| 类型 | 用途 |
|---|---|
| 固定比例规则 | 按项目金额乘以固定比例 |
| 动态比例/积分规则 | 按积分和绩效总额计算积分单价 |
| 固定金额规则 | 按人次、次数、份数发放固定金额 |
| 计件规则 | 按项目数量、单价、岗位系数计算 |
| 阈值/基准线规则 | 达到基准线后对超出部分计算 |
| 评分规则 | 多指标评分、权重、等级系数 |
| 扣罚/质量控制规则 | 投诉、错误、质控不合格等扣减 |
| 人工调整规则 | 对计算结果进行人工增减调整并保留原因 |

人工调整不替代原始规则结果，只在流水线后段叠加。

---

## 3. 规则参数

规则参数必须配置化，至少覆盖：

- 比例
- 固定金额
- 计件单价
- 岗位系数
- 项目积分
- 总额口径
- 阈值/基准线
- 评分指标
- 指标权重
- 等级系数
- 扣罚条件
- 扣罚金额或扣罚比例
- 是否允许叠加
- 是否互斥
- 生效时间和失效时间

制度文件中的金额和比例只能作为默认模板示例，不得写死到代码。

---

## 4. 规则适用范围

规则适用范围用于决定一条规则是否命中绩效原子数据。

范围维度包括：

- 人员
- 岗位
- 科室
- 全院
- 项目
- 项目分类
- 人员类型
- 时间周期
- 数据来源
- 是否冲减/是否作废

规则优先级固定为：

1. 人员
2. 岗位
3. 科室
4. 全院

当多条规则同时命中同一绩效原子数据时，先按适用范围优先级排序，再按规则类型阶段执行，再按规则版本和生效时间判定。

---

## 5. 规则版本、生效时间与状态

每条规则必须具备版本概念：

- 规则标识：识别同一规则族
- 版本号：识别规则族下的具体版本
- 生效时间：规则开始适用时间
- 失效时间：规则停止适用时间，可为空
- 状态：草稿、启用、停用、归档
- 修改原因：记录规则调整背景

计算时必须按绩效原子数据发生时间匹配对应规则版本。历史计算结果应保留当时使用的规则版本，避免后续规则修改污染历史结果。

---

## 6. 执行器机制

规则引擎采用“规则定义 + 执行器注册 + 流水线调度”的机制。

每种规则类型对应一个执行器：

| 执行器 | 处理规则 |
|---|---|
| 比例执行器 | 固定比例、动态比例 |
| 固定金额执行器 | 固定金额 |
| 计件执行器 | 计件单价、岗位系数 |
| 阈值执行器 | 阈值、基准线、超额部分 |
| 评分执行器 | 指标权重、评分、等级系数 |
| 扣罚执行器 | 质量扣罚、投诉扣罚、错误扣罚 |
| 调整执行器 | 人工调整 |

执行器通过规则类型注册和调度，不通过散落在业务流程中的if/else判断。新增规则类型时，应新增规则定义和执行器，不修改既有执行器的内部判断。

---

## 7. 多规则叠加机制

规则叠加需要明确三类关系：

| 关系 | 说明 |
|---|---|
| 可叠加 | 多条规则结果累加 |
| 互斥 | 只取优先级最高或指定规则 |
| 修正 | 后一类规则基于前一阶段结果修正 |

叠加顺序必须遵循标准计算流水线：

1. 基础绩效：比例、固定金额、计件
2. 阈值/基准线
3. 评分模型
4. 扣罚/质量控制
5. 人工调整

不得在基础计算前执行扣罚，不得在扣罚后再改变基础规则命中结果。

---

## 8. 阈值、评分、扣罚处理顺序

处理顺序固定为：

1. 先计算基础绩效
2. 再处理阈值/基准线，确定可计提范围或超额部分
3. 再处理评分模型，形成评分系数或等级系数
4. 再处理扣罚/质量控制，形成扣减项
5. 最后处理人工调整

示例含义：

- 阈值决定哪些数据可以进入绩效计提
- 评分影响规则结果的系数或等级
- 扣罚在规则结果之后扣减
- 人工调整必须保留原始计算结果和调整原因

---

## 9. 退费/冲减规则

退费、作废、退药等冲减处理发生在规则匹配之前。

规则引擎收到的绩效原子数据应已标记：

- 是否冲减
- 是否作废
- 原始单号/业务单号
- 对应正向业务记录
- 冲减金额或数量

规则引擎不应忽略冲减数据。计算结果应体现净额或冲减后的数量，追溯中必须能看到正向记录和冲减记录。

---

## 10. 计算追溯要求

每次规则执行必须生成追溯信息：

- 命中的绩效原子数据
- 命中的规则及版本
- 适用范围命中原因
- 计算周期
- 输入数量和金额
- 中间计算结果
- 阈值、评分、扣罚、调整的处理过程
- 最终结果

追溯信息用于结果解释、报表钻取、差异核查和历史复算对比。

---

## 11. 禁止事项

- 禁止在执行器中写死制度金额和比例
- 禁止用人员姓名、科室名称硬编码规则
- 禁止以页面选择替代规则匹配
- 禁止绕过规则版本直接使用最新规则计算历史数据
- 禁止把人工调整覆盖原始计算结果
- 禁止将权限角色作为V1规则适用维度
